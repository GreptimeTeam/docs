# DDL events

DDL events are recorded asynchronously and on a best-effort basis. A lifecycle
normally has a `Running`/`Submitted` row followed by a `Done`/`Succeeded` row.
The terminal row is regenerated by the procedure's `event()` hook, not copied from
the submitted row, so family fields can be dropped or recomputed. Terminal DDL
rows use JSON `null` for `payload`.

Terminal rows retain stable object names from the Procedure state. Some create
operations add an allocated ID only when the terminal output supplies it.

See [Event data model](/user-guide/deployments-administration/monitoring/events/event-data-model.md)
for shared columns and lifecycle states.

## Database events

```sql
SELECT timestamp, type, procedure_state AS state,
       json_get_string(procedure_trigger, 'type') AS trigger_type,
       json_to_string(payload) AS payload
FROM greptime_private.events
WHERE catalog_name = 'greptime'
  AND schema_name = '<database_name>'
  AND type = '<event_type>'
ORDER BY timestamp;
```

Database event types are `create_database`, `alter_database`, and `drop_database`.
Event rows retain the catalog and schema locator; the database name is used
only as a filter and is not included in the output.

## Table events

```sql
SELECT timestamp, type, procedure_state,
       json_get_string(procedure_trigger, 'type') AS trigger_type,
       table_name, table_id, json_to_string(payload) AS payload
FROM greptime_private.events
WHERE catalog_name = 'greptime'
  AND schema_name = '<database_name>'
  AND type = '<event_type>'
ORDER BY timestamp;
```

The reusable query returns all objects of the selected event type in the
database. To narrow it to one object, optionally add
`AND table_name = '<table_name>'` to the `WHERE` clause.

Stable `table_name` values are retained in the terminal rows. `create_table`
and `create_logical_tables` add a `table_id` only when the `Done` output
supplies one. `alter_table`, `truncate_table`, and `drop_table` retain IDs
already known to the procedure. `create_logical_tables` and
`alter_logical_tables` are source-supported logical-table event types.
`undrop_table` and `purge_dropped_table` are Enterprise-only.

## Flow events

Flow rows retain `catalog_name` and `flow_name`. `schema_name` is SQL `NULL` for
flows, while `flow_name` remains available. `create_flow` adds `flow_id` when
available, and `drop_flow` retains the known ID.

```sql
SELECT timestamp, type, procedure_state,
       json_get_string(procedure_trigger, 'type') AS trigger_type,
       catalog_name, schema_name, flow_name, flow_id,
       json_to_string(payload) AS payload
FROM greptime_private.events
WHERE catalog_name = 'greptime'
  AND flow_name = '<flow_name>'
  AND type = '<event_type>'
ORDER BY timestamp;
```

**`create_flow`**

## View events

View rows retain stable `view_name` values. `create_view` adds `view_id` only
when available, and `drop_view` retains the known ID.

```sql
SELECT timestamp, type, procedure_state,
       json_get_string(procedure_trigger, 'type') AS trigger_type,
       view_name, view_id, json_to_string(payload) AS payload
FROM greptime_private.events
WHERE catalog_name = 'greptime'
  AND schema_name = '<database_name>'
  AND view_name = '<view_name>'
  AND type = '<event_type>'
ORDER BY timestamp;
```

The database name is used only as a filter and is not included in the output.
